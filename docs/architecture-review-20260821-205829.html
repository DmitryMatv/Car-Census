1 · Make the Retrieval match verdict a typed decision

Strong in-process

mmr/retrieval_cache.py:462–663 · mmr/trafficeye.py:249–254, 301–306

Before — stringly-typed wire
MMRRetrievalStore.lookup()
exact_match no_match calibration_missing embedding_conflict exact_ineligible insufficient_neighbors …
emits reason: str
TrafficEyeClient
re-implements the subset: {exact_conflict, exact_ineligible, embedding_conflict, embedding_ineligible} → force_api_request
new blocking reason in store ⇒ silent fail-open here
After — typed verdict at the seam
Retrieval cache — deep module
lookup() decides everything: match kind, reuse safety, audit action (Shadow retrieval vs enforce)
LookupVerdict { reusable, force_fresh_api }
TrafficEyeClient — thin adapter
verdict.reusable ? return API-confirmed reuse : request & record

Problem. The Retrieval cache’s interface is a bag of magic strings; the client re-interprets a hardcoded subset into force_api_request, so the conservative-reuse policy the ADR mandates survives only because both sides happen to agree today.

Solution. Return a closed LookupVerdict carrying the decisions the caller actually needs (reusable, force_fresh_api) and move audit-action selection inside the store, which already knows mode and match kind.

  • locality: reuse policy lives in one module
  • depth: interface shrinks to one verdict value
  • fail-open drift becomes unrepresentable
  • leverage: integration tests assert the type, not strings

Problem. Classification constructs its TrafficEye dependency inline (with a production branch that exists only to serve a test double), so tests can only reach the interface by monkeypatching, and “where the shared Retrieval cache lives” is encoded in three modules.

Solution. Inject a small VehicleRecognizer protocol matching what TrafficEyeClient already exposes; a default adapter builds it via one factory that also owns cache-dir resolution, moved into RunStore/layout.

  • two adapters justify the seam: HTTP, fake
  • tests cross the same seam as callers
  • locality: cache location defined once
  • interface stops lying about hidden I/O

5 · Split the annotator’s implementation: pure layout, injected emoji raster

Speculative ports & adapters

Before — one 830-line implementation
annotate(frame, tracks, labels…) — small interface ✓

After — internals get their own seams

EmojiRaster seam — Pillow adapter default

cv2 drawing stays put
“what a label says” (render.py) and “how it’s drawn” stop sharing emoji vocabulary by side effect

Problem. The annotator’s interface is small but its implementation mixes pure layout, environment-dependent global caches, and frame-order-dependent mutable state, so every test must go through rendered pixels.

Solution. Extract pure LabelLayout computation, inject an EmojiRaster protocol (Pillow as the default adapter), and move animation state into an object the caller owns per video.

  • most pixel tests become plain assertions
  • font absence is a constructor concern
  • annotator reusable across videos again
  • internal seams, external interface unchanged

6 · Collapse the FFmpeg writer twins; make smoothing’s signal explicit

Speculative in-process

utils/video.py:62–135, 138–216, 489–549 · pipeline/render.py:159–160 · pipeline/smooth.py:644–662 · pipeline/default_stages.py:15–29

Before — copy-paste twins + covert channel
FFmpegRawVideoWriter
-cq pix_fmt nv12 stderr handling
FFmpegCPUFrameWriter
-crf -threads 0 same stderr handling, again
+ OpenCV fallback pasted three times in build_frame_writer
covert channel: render decides raw-vs-smoothed by frames_path == render_frames_path — smooth’s return value doubles as a boolean
After — one parameterized implementation
_FFmpegPipeWriter(base_args, codec_args)

Problem. Two ~95% identical FFmpeg writers and a tripled OpenCV fallback mean every fix lands twice, and render↔smooth communicate through path equality — a covert channel nothing type-checks.

Solution. One parameterized pipe writer plus a single fallback helper; smoothing returns an explicit (path, used_smoothing) pair.

  • mechanical; 16 writer tests already exist
  • mode signal survives refactoring
  • deletes ~80 lines of duplication
